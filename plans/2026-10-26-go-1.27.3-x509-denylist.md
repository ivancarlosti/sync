# Plan — Go 1.27.2 → 1.27.3 (`crypto/x509` distrust list)

- **Date:** 2026-10-26
- **Repo:** https://github.com/ivancarlosti/sync
- **Goal:** clear `GO-2026-6809` (`CVE-2026-111943`). In Go 1.27.0–1.27.2
  `crypto/x509.Certificate.Verify` accepts a set of known-compromised
  intermediate CA certificates that are no longer trusted; 1.27.3 makes
  `Verify` reject them. The standard library is linked into the binary, so only
  a rebuild with 1.27.3 fixes the shipped artefact.
- **Related:** follows [`2026-10-15-npm-advisories-psp-sourcemap.md`](./2026-10-15-npm-advisories-psp-sourcemap.md),
  which moved the toolchain to `go1.27.2` for the HTTP/2 and TLS advisories.
  This file supersedes its toolchain rows.

## 1. Findings

### Before

`govulncheck ./...` on `main` @ `3df9fb6` (go1.27.2): **1 reachable vulnerability**.

| Vulnerability | Package | Found in | Fixed in | Reachable |
|---|---|---|---|---|
| `GO-2026-6809` | `crypto/x509` (standard library) | `go1.27.2` | `go1.27.3` | **yes** |

The scanner's trace:

```text
internal/providers/google/drive.go:315:77: google.cancelReadCloser.Read
  calls http.readWriteCloserBody.Read, which eventually calls x509.Certificate.Verify
```

That path is representative of every outbound TLS connection the process makes:
OIDC/Keycloak, Google and Microsoft Graph logins, shoutrrr notifications and the
database. Since the x509 code is compiled into the binary, patching a module
cannot fix it — only a rebuild with the patched stdlib can.

### The fix is entirely in the toolchain

Diffing the cached SDKs (`src/crypto/x509`, 1.27.2 → 1.27.3) shows the change:

- `distrustedSPKIHashes` — eight SHA-256 hashes of SPKIs from certificates that
  are no longer trustworthy — plus `containsDistrustedSPKIHash` in `verify.go`,
  and the chain filter in `verifyChain`;
- the same filter in the platform verifiers `root_darwin.go` and `root_windows.go`.

### Modules were deliberately not bumped

`go list -m -u all` offers newer releases for most direct and indirect modules
(gin, gorm drivers, kiota/msgraph, `x/*`), but none of them closes this advisory:
the vulnerable code is `crypto/x509`. The only remaining module-level finding is
the known, unfixable `GO-2026-5932` (`golang.org/x/crypto/openpgp` — package not
imported). Bumping modules inside a security hotfix would widen the blast radius
without reducing a single reachable vulnerability, so it was left out.
